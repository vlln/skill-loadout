# 聊天菜单分层

## 交互契约

- 主层：编组多选、已生效 Skills 入口、存在项目技能时的项目子菜单。逐组取消，不提供清空全部。
- 不平铺生效技能，不重复新建/编辑编组、技能库、管理、刷新和历史说明。
- 项目技能用宿主普通子菜单，通过会话排除勾选。已生效技能进入单一原生 Menu 搜索面板，以 Input/MenuGroup/MenuItemButton 组合分组；可返回，不让输入框嵌进菜单按钮。简易 submenu 不支持分组标题（type:label 会产生空行），不能混用。
- 实际生效技能子菜单可打开只读预览；按可用成员的规范名称解析真实 root/name，不用列表下标推测来源。歧义映射禁用预览。
- 预览关闭、切会话及新请求使旧请求结果失效；失败可在预览内重试。
- 管理统一在设置完成，不影响默认编组及会话选择后端规则。

## 验证范围

本轮使用持久私有 HOME/DSH_HOME，验收固定端口 56372，不修改真实用户配置。构建、类型检查与完整 npm test 通过。真实 Chrome 验证主菜单无管理入口、连续勾选两组后保持打开、原生生效名单子菜单展开、点击技能后只读正文实际加载成功，无 pageerror。源代码测试覆盖预览失败重试、规范来源选择、关闭后迟到响应、切会话迟到响应及项目排除别名。浏览器项目子菜单的触摸交互本轮未单独实测，不将宿主原生支持等同于该项验收。
