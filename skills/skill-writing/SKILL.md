# 写一份 skill

只回答两件事：**什么样算合格**（判据），**怎么写更好**（风格）。

## 事实：官方规范怎么说

来源：Agent Skills 规范与 skill-creation 指南（`agentskills.io`），核对 **2026-10-19**。宿主是最终权威，换宿主或升级后重核。

一个 skill 是一个目录，至少含 `SKILL.md`；`scripts/`、`references/`、`assets/` 可选。目录名必须等于 `name`。

| 字段 | 必须 | 约束 |
|---|---|---|
| `name` | 是 | 1–64 字符，仅 `a-z0-9-`，首尾及连续连字符禁止，必须等于父目录名 |
| `description` | 是 | 1–1024 字符，写清"做什么"和"何时用" |
| `license` | 否 | 许可名，或指向随包许可文件 |
| `compatibility` | 否 | 1–500 字符，环境要求；多数 skill 不需要 |
| `metadata` | 否 | 字符串键值表——客户端自定义属性的**官方位置** |
| `allowed-tools` | 否 | 空格分隔的预批准工具，实验性，各客户端支持不一 |

- 渐进披露三层：启动只读 `name` + `description`（约 100 tokens/份）；激活读整个正文（建议 <5,000 tokens）；`scripts/`、`references/`、`assets/` 按需。正文建议 <500 行。
- **`description` 会被宿主截断，长度上限不止一处**：规范上限 1024 字符；DeepSeek Harness 的会话目录默认只显示前 **500** 字符（`catalogDescriptionMaxLength`，核对 2026-10-19）。所以判定性的句子必须放在最前面，后面的内容随时可能不被读到。
- 文件引用用**相对 skill 根目录的路径**，层级保持一层。
- 官方 `skills-ref validate <dir>` 只校验 frontmatter 与命名，不校验内容质量。

## 判据：合格线

**frontmatter**

- 六个字段名照抄规范，不自造顶级字段；自定义内容一律进 `metadata`。
- YAML 必须从文件第 0 字节开始：BOM 或前置空行会让整份 frontmatter 失效。
- 值里含 `: ` 或 `#` 时加引号。未引号的冒号是最常见的静默失败。

**三角色不互串**

| 读者 | 文件 | 不该出现 |
|---|---|---|
| 决定是否安装的人 | 仓库 README | agent 工作流、内部设计理由 |
| 使用它的 agent | `SKILL.md` + `references/` | 安装说明、维护者笔记 |
| 维护者 | README 旁注、`docs/` | 运行期才需要的指令 |

**独立**

- 不引用其他 skill，不提它们的名字，不假设它们存在。
- 不属于本文的内容不写；需要的内容写成本文的最小充分版。

**断言必须能失败**

- 机械校验只证明格式对，不证明能用。
- 至少做一次负控：删 `description`、改错 `name`、把两件无关事塞进一个触发，确认检查会报错。从不失败的校验不是证据。

**事实带来源与日期**：任何"宿主支持 / 最多多少字符 / 现在是最新版"的断言都标核对日期，否则它比规则先过期。

## 风格：怎么写更好

**description**

- 用"当……时使用本 skill"的祈使句，写用户想达成的事，不写内部机制。
- 顺序固定：**先写触发场景，再写能力，最后才是实现细节**。宿主可能只读前 500 字符。
- 写满 1–3 个用户会用的名词（任务名、产物名），让匹配有落点；同义词堆叠没有用。
- 一条描述需要 `and` 连接两件无关的工作，就是该拆的信号。
- 近邻的区分不写进描述，交给查询集测。

**正文**

正文只承担五样东西：流程、默认值、脆弱约束、gotchas、校验回环。其余（通用知识、标准工具用法、复述文档）都是上下文税。

正文的形状由它回答的问题决定——先定主面，再决定写什么：

| 主面 | 写什么 | 不写什么 |
|---|---|---|
| 流程 | 顺序、关口、谁决定、交接物 | 具体命令、判定细则 |
| 质量 | 判据、风格、反例、负控 | 何时做、装在哪 |
| 执行 | 命令、参数、产物、验什么 | 写作判据、审批 |

通用技巧，按需要挑，不是清单：

- **gotchas**：违反合理假设的具体事实——现象、原因、最小修法。放正文，别放深的 reference。
- **模板**：要固定输出格式时给具体骨架，比散文描述可靠。
- **清单**：多步且有依赖或关口时给。
- **校验回环**：做完跑校验，失败就修，通过才继续。
- **先计划后执行**：批量或破坏性操作，先产出计划，对照事实校验后再执行。

写作口径：

- 只写模型不写就会做错的东西。
- 默认给一个，另给一条后路；不要摆一堆等权选项。
- 多解可用时讲理并给默认，脆弱处（精确命令、顺序、格式）钉死。
- 一段讲一件事；判据用"必须 / 不得 / 应当"，不用"注意""确保"。

## 输出

写完或审完给四项：它回答哪个问句；作用域是什么；哪些句子是事实（带来源日期）；哪些是判据与风格。
